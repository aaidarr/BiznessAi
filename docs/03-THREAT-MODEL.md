# Модель угроз (STRIDE-ориентированная, кратко)

Активы: учётные записи владельцев, токены TG/VK/LLM, база знаний, ПДн клиентов бизнеса (имя, телефон), репутация бота (ложные ответы).

| # | Угроза | Вектор | Мера | Остаточный риск |
|---|---|---|---|---|
| T1 | Перебор паролей | /login | argon2id, счётчик неудач + блок 15 мин, лимит по IP | Распределённый перебор: нужен WAF/Captcha |
| T2 | Кража сессии | XSS, перехват | HttpOnly+Secure+SameSite=Lax, токен в БД в виде хэша, CSP, автоэкранирование Jinja | Вредоносные расширения у пользователя |
| T3 | CSRF | Формы кабинета | Токен сессии в каждой POST-форме, проверка заголовка Origin | — |
| T4 | IDOR / обход изоляции | Подмена id в URL | Любая выборка фильтруется `business_id`; тесты изоляции | Новые эндпоинты: покрывать тестами |
| T5 | SQL-инъекции | Ввод | Только ORM / параметры | — |
| T6 | SSRF через краулер | URL сайта | Только http(s), порты 80/443, проверка резолва (не private/loopback/link-local/metadata), проверка IP сокета после подключения, ручная обработка редиректов (≤3), лимит размера/времени | Редкие обходы через DNS rebinding между проверкой и connect — смягчено проверкой peer IP |
| T7 | Загрузка файлов | /kb/upload | Только txt/md/pdf, ≤2 МБ, проверка расширения и сигнатуры, текст извлекается, файл не сохраняется и не исполняется | Парсер pypdf: обновлять, лимит страниц |
| T8 | Prompt injection | Страницы сайта, сообщения клиента | Фрагменты как данные в разделителях; результат проверяется guard (числа/контакты/модальности); бот не выполняет действий по тексту модели; запись — детерминированный сценарий | Ложные нечисловые утверждения возможны; режим «выдержка» устраняет, снижая гибкость |
| T9 | Утечка ключей TG/VK/LLM | БД, логи | Шифрование Fernet, ключ из окружения, токены не логируются, маскирование в UI | Компрометация сервера целиком |
| T10 | Подделка вебхуков | /hook/tg, /hook/vk | Секрет в пути + заголовок X-Telegram-Bot-Api-Secret-Token / secret VK, сравнение constant-time | — |
| T11 | Злоупотребление виджетом (спам, расход токенов) | Публичный endpoint | Лимиты на IP и ключ, лимит длины, проверка Origin, лимит тарифа, кэш | Бот-сеть с разных IP |
| T12 | Двойная запись / гонка | Параллельные запросы | Транзакция + блокировка ресурса + уникальный ключ | — |
| T13 | Утечка ПДн клиентов | Логи, бэкапы | ПДн не пишутся в логи; бэкапы шифруются на хосте оператором; срок хранения диалогов настраивается (по умолчанию 180 дн.) | Правовая сторона требует юриста |
| T14 | Захват чужого бренда (бот чужой компании) | Регистрация с чужим сайтом | Подтверждение владения сайтом до включения публичных каналов | Бизнесы без сайта не проверяются |
| T15 | XSS в виджете/админке | Сообщения клиента в кабинете | Экранирование, `textContent` в JS, CSP без inline-скриптов | — |
| T16 | Отказ в обслуживании | Тяжёлый краулинг, большие тела запросов | Лимит размера тела, очередь и лимит одного краула в час, таймауты | Нужна защита на уровне nginx/CDN |
| T17 | Злоупотребление регистрацией | Массовые аккаунты | Лимит регистраций с IP; email не подтверждается (риск принят в MVP) | Спам-аккаунты |
| T19 | Формулы в CSV (клиент вводит `=HYPERLINK(...)` вместо имени, владелец открывает выгрузку в Excel) | `/app/reports/export/*.csv` | Ячейки, начинающиеся с `= + - @`, экранируются апострофом; лимит 20 выгрузок в час; запись в аудит | Другие программы-таблицы с иными правилами |
| T20 | Подмена чужого `document_id`/`message_id`/`booking_id` в новых разделах кабинета | `/app/bot/*`, `/app/calendar/*` | `owned()` и проверка `business_id` во всех обработчиках, тесты на каждый новый эндпоинт | Новые эндпоинты нужно покрывать так же |
| T18 | Подмена платежа | Фейк-вебхук ЮKassa | Статус платежа перепроверяется запросом к API ЮKassa по id, суммы сверяются | Не проверено без боевых ключей |

Проверки: тесты безопасности (`tests/test_security.py`), `bandit`, `pip-audit`, ручной чеклист OWASP ASVS L1 в `docs/06-SECURITY-CHECKLIST.md`.
