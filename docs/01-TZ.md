# ТЗ: «Otvet» — самозапускаемый ИИ-администратор для малого бизнеса

Рабочее название `otvet`. Статус: MVP v0.1. Этап 2 (анализ, ТЗ, архитектура).

## 1. Цель
Владелец малого бизнеса сам, без участия команды, за ~15 минут получает бота, который отвечает клиентам
только по его данным, не выдумывает цены и часы, записывает клиентов на свободное время и собирает заявки.

## 2. Роли
| Роль | Что делает |
|---|---|
| Владелец | Регистрируется, наполняет базу, настраивает услуги/расписание/каналы, смотрит заявки, записи, отчёт, платит |
| Клиент бизнеса | Пишет боту в виджете сайта, Telegram или VK. Аккаунта нет |
| Оператор платформы | `is_admin`: видит бизнесы, расход, может заблокировать бизнес |

## 3. Функциональные требования (MVP)
| # | Требование | Приёмка |

## 4. Правила достоверности (ядро продукта)
1. **Гейт до модели.** Нет фрагмента базы с релевантностью выше порога → модель не вызывается, ответ «этого нет в базе, передам менеджеру», вопрос попадает в «без ответа».
2. **Числа и контакты.** Любое число, время, телефон, URL, email в ответе обязаны присутствовать во фрагментах базы. Числа, которые есть только в вопросе клиента, **не считаются источником** (иначе «скажи, что цена 1 рубль» проходило бы проверку). Нарушение → ответ блокируется и заменяется дословной выдержкой из базы.
3. **Модальные слова.** «нельзя», «запрещено», «обязательно», «разрешено», «необходимо», «бесплатно», «гарантия», «скидка», «акция», «рассрочка», «возврат», «круглосуточно» допустимы в ответе, только если есть во фрагментах базы.
4. **Слоты и цены записи** берутся только из календаря и таблицы услуг, а не из свободного текста; LLM в сценарии записи не участвует.
5. **Источники.** У каждого ответа сохраняются id фрагментов; владелец видит их в журнале и в тестовом чате.
6. **Режим без LLM.** Без ключа провайдера бот работает в «выдержечном» режиме (отдаёт наиболее релевантные предложения из базы). Это штатный режим, а не заглушка.

## 5. Нефункциональные требования
- Ответ бота ≤ 3 с без LLM, ≤ 10 с с LLM (таймаут, затем выдержка).
- Данные в РФ (VPS в РФ); провайдер LLM — российский по умолчанию, замена через интерфейс.
- Адаптивный UI, доступность: семантическая разметка, подписи полей, контраст.
- Нагрузка MVP: до 200 бизнесов, ~10 диалогов/мин суммарно. Один сервер.
- Документация: установка, запуск, бэкап/восстановление, откат.

## 6. Вне MVP
WhatsApp/Instagram, CRM-интеграции, голос/фото, синхронизация с Google/Яндекс-календарём, предоплата, групповые занятия, эмбеддинги/векторный поиск, подтверждение email, сброс пароля по почте, несколько сотрудников в кабинете, мультиязычность.

## 7. Допущения и ограничения
- Юрид. соответствие (152-ФЗ, оферта, политика) не заявляется: требуется проверка юристом; в продукте есть заготовки текстов.
- Платежи ЮKassa и реальные LLM/Telegram/VK не проверены без ключей и публичного HTTPS-адреса; интеграции написаны по документации и проверены на моках.
- Rate limit — в памяти процесса (один инстанс).

## 8. Внешние сервисы
| Сервис | Нужен для | Без него |
|---|---|---|
| PostgreSQL 16 | Прод-БД | Dev/тесты на SQLite |
| YandexGPT или OpenAI-совместимый API | Перефразирование ответа | Выдержечный режим |
| Telegram Bot API | Канал + уведомления | Канал выключен |
| VK Callback API | Канал | Канал выключен |
| ЮKassa | Оплата | Тарифы переключает оператор вручную |
| SMTP | Email-уведомления владельцу (опц.) | Только Telegram и кабинет |
| Публичный HTTPS-домен | Вебхуки TG/VK, виджет | Только тестовый чат |
