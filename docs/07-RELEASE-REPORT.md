## 4. Нужно до публичного запуска (блокеры)
1. **Подтверждение email и сброс пароля.** Сейчас забытый пароль восстанавливает оператор вручную, регистрация защищена только лимитом по IP.
2. **Юридическая часть:** политика конфиденциальности, оферта, согласие на обработку ПДн клиентов бизнеса, регистрация оператора ПДн, договор поручения между вами и бизнесами. Тексты в продукте — заготовки; соответствие 152-ФЗ **не заявляется**.
3. **Первый деплой и учебное восстановление** из бэкапа на стенде.
4. **Прогон с реальными Telegram/VK и LLM-ключом**, включая работу вебхуков за вашим HTTPS.
5. **Удаление данных по запросу** (аккаунт, диалоги) пока выполняется оператором вручную через БД; нужна кнопка или процедура.

## 5. Известные ограничения и остаточные риски
См. `06-SECURITY-CHECKLIST.md`. Главные: лимиты в памяти процесса (один инстанс); проверка достоверности надёжно ловит числа, контакты, ссылки и перечисленные слова, но не любое выдуманное нечисловое утверждение; поиск лексический (редкие синонимы дают безопасный отказ); без WhatsApp/Instagram, CRM, голоса и фото, предоплаты и синхронизации с внешним календарём.

## 6. Личный кабинет (версия 0.2.0)
Подробности и исследование аналогов: `docs/08-CABINET.md`. Проверено: миграция `0002` на PostgreSQL с уже существующими данными (вверх, вниз, вверх, `alembic check` без расхождений); все страницы кабинета отдают 200 и проходят проверку строгой CSP; кабинет вручную просмотрен в реальном браузере (календарь, карточка записи, отчёты, ответы, мобильная ширина); сценарий «шаблон → услуги и расписание → запись клиента через виджет → запись в календаре и отчёте» пройден в браузере.

Дефекты, найденные при этой работе и исправленные (у каждого есть регрессионный тест): отменённая запись навсегда блокировала слот в БД; адрес обрезался на «г.»; календарь падал на дате вне диапазона; колонки дня перекрывали заголовок недели; сначала недоработанная загрузка `kb.get_index` не учитывала приоритет ответов владельца.

Не проверено: календарь и отчёты на больших объёмах (агрегация отчёта выполняется в Python и ограничена 20 000 строк), реальные устройства и скринридеры, работа нескольких одновременных пользователей кабинета.

## 7. Рекомендуемый порядок дальше
1. Деплой на стенд, чеклист из `05-DEPLOY.md`.
2. Подключить YandexGPT (или OpenAI-совместимый API) и сравнить на реальных базах режимы `extractive` и модель по автопроверке.
3. Пилот с 3 бизнесами одной ниши, собрать метрики: время до первого рабочего бота, доля ответов из базы, число отказов, число записей.
4. Закрыть блокеры из раздела 4.
5. После пилота: эмбеддинги, WhatsApp через BSP, CRM-интеграции — по данным пилота.
